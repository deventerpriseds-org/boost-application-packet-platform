## 0. What was measured, and against what

**The denominator is the prototype**, read directly: `docs/qc-evidence/qc/*.jsx` (2,410 lines
across `assets.jsx` 487, `packet.jsx` 573, `evidence.jsx` 447, `shell.jsx` 131, `assist.jsx` 123,
`data.js` 649) plus `Packet QC Prototype.html`. Rows are grouped by `SPEC.md` §4.1–§4.12 so every
row is citable against the handover spec.

**A row = one user-visible control, panel, chip, state or affordance.** Not a string, not a demo
value, not a colour token. `UI-GAP-REGISTER.md:41-44` already establishes why string equality is
the wrong instrument, and `COMPONENT-INVENTORY.md:690-700` measured that **26 of 40** of that
register's printed `resume` rows are SafetyIQ demo values rather than components.

**Verdict vocabulary** (inherited from `COMPONENT-INVENTORY.md:24-25` so the two documents
compare):

| Verdict | Meaning |
|---|---|
| **BUILT** | The element and its states exist in the app. A rename is not a gap. Requires a `file:line`. |
| **PARTIAL** | The element exists; named states, colours, transitions or mounts are missing. Requires a `file:line`. |
| **ABSENT** | No counterpart in the app. Never asserted from a single-file grep (see method limits, §14). |
| **DELIBERATE** | Diverges or is omitted **by a recorded decision**. Cited to `PULL-CANDIDATES.md`, `.claude/actions.md` or `.claude/DEFERRED.md`. **Counted separately — this is not a gap.** |
| **NOT-IN-PROTOTYPE** | The prototype does not implement it either (a dead handler, a mockup-only affordance). Cannot be "missing from the app". Excluded from the denominator. |
| **OUT-OF-SCOPE** | `SPEC.md:8` §8 or §4.12 says *do not build it*. Excluded from the denominator. |

## 15. WHAT THIS METHOD PROVES, AND WHAT IT DOES NOT

**Reading code proves a component exists in source. It does not prove it renders correctly at
runtime, with this owner's real data, in a browser.** Every BUILT verdict above should be read as
*"the component and its states are in the source at this line"* — never as *"a user sees this
today"*.

Three specific limits, and what would close each:

**1. A component can be built and never reach the screen for want of data.** Half of §4.5's newest
rows depend on payload shape: the keyword chips need `requirement.model_keyword` to be non-empty on
this opportunity, the findings list needs `findingsByField(result)` to return rows, the state
colour needs `fieldSev` to be non-null. A field with no findings correctly renders *no colour* —
which is indistinguishable, by reading, from a colour that never renders. **These need
`npm run test:margin` (`app/test/browser/run-field-margin.mjs`) — it renders the field margin for
real.**

Rows that need it: **4.5-6** (state colour), **4.5-13/-14/-15** (highlighting and the linked
hover), **4.5-23** and **4.4-28** (the findings list), **4.5-28/-31/-36** (chips, detail panel,
`not in this text`), **4.4-32** (`Nothing to review on this asset.`), **4.5-18** (the `identical`
original state).

**2. A component can be built and never reach the screen for want of a mount.** This document read
every relevant import list, which catches the `CorrectionRow` class of error — but a mount inside a
branch that never evaluates true would still read as BUILT. **These need `ui-verify.yml` against
